# 照片同步服务

## 功能概述

照片同步服务负责从远程URL下载照片到本地目录，支持按订单组织文件结构，并具备完善的重试机制来处理网络异常。

## 目录结构

同步后的照片按以下结构组织：

```
输出根目录/
└── {年份}/                    # 如：2024
    └── {月份}/                # 如：6月
        └── {日期}/            # 如：6-01
            └── {收货人}-{订单号}/   # 如：张三-ORDER123
                ├── {规格1}/   # 如：3寸-满版
                │   ├── 照片1.jpg
                │   └── 照片2.jpg
                └── {规格2}/   # 如：4寸-留白
                    ├── 照片3.jpg
                    └── 照片4.jpg
```

## 智能异步重试机制

### 重试策略

1. **快速失败 + 异步重试**: 主流程不阻塞，失败的照片加入异步重试队列
2. **最大重试次数**: 默认3次（可配置）
3. **动态超时时间**: 随重试次数递增
   - 第1次尝试: 30秒
   - 第2次重试: 60秒  
   - 第3次重试: 90秒
   - 第4次重试: 120秒（最大值）

4. **指数退避延迟**: 重试前等待时间递增
   - 第1次重试前: 2秒
   - 第2次重试前: 4秒
   - 第3次重试前: 8秒

5. **协程池**: 使用协程池并发处理重试任务，提高效率

### 可重试的错误类型

系统会自动识别以下错误类型并进行重试：

- **网络超时错误**:
  - `context deadline exceeded`
  - `Client.Timeout exceeded while awaiting headers`
  - `i/o timeout`

- **网络连接错误**:
  - `connection reset by peer`
  - `connection refused`
  - `no such host`
  - `network is unreachable`
  - `EOF`

- **服务器临时错误**:
  - HTTP 5xx 状态码

### 不会重试的错误

以下错误类型不会重试，直接标记为失败：

- HTTP 4xx 客户端错误（如404, 403, 401等）
- URL格式错误
- 文件系统权限错误

## 配置参数

```yaml
SyncConfig:
  BatchSize: 50                    # 每批处理的订单数量
  OutputPath: /path/to/output      # 照片输出根目录
  
  # 下载重试配置
  DownloadTimeout: 30              # 初始下载超时时间（秒）
  MaxRetries: 3                    # 最大重试次数
  RetryBaseDelay: 2                # 重试基础延迟时间（秒）
  MaxDownloadTimeout: 120          # 最大下载超时时间（秒）
  
  # 异步重试配置
  AsyncRetry: true                 # 是否启用异步重试
  RetryWorkers: 5                  # 重试协程池大小
  RetryChannelSize: 1000           # 重试队列大小
```

## 状态管理

### 订单状态

- **Pending (0)**: 待处理
- **Processing (1)**: 处理中
- **Completed (2)**: 已完成

### 照片状态

- **Pending (0)**: 待下载
- **Success (1)**: 下载成功
- **Failed (-1)**: 下载失败

### 处理逻辑

1. **订单处理**: 只有当订单中所有照片都成功下载时，订单才会被标记为已完成
2. **失败处理**: 部分照片下载失败时，订单保持"处理中"状态，等待重试
3. **重试机制**: 系统会定期重试失败的照片和处理中订单的失败照片

## 文件安全

- 使用临时文件下载，下载完成后原子性重命名，避免部分写入的文件
- 每次同步前清空订单目录，确保文件集合的一致性
- 自动清理下载失败的临时文件

## 监控和日志

系统提供详细的日志记录：

- 下载进度和状态
- 异步重试队列状态
- 重试协程工作日志
- 重试次数和原因
- 超时和网络错误详情
- 订单和照片状态变化

可通过日志监控系统性能和识别问题模式。

## 性能优势

### 异步重试机制的优势

1. **主流程不阻塞**: 照片下载失败时，主流程立即继续处理下一张照片
2. **并发重试**: 多个协程并发处理重试任务，提高重试效率
3. **资源优化**: 重试队列避免了重复查询数据库
4. **优雅停机**: 支持协程的正确停止和资源清理

### 适用场景

- 网络不稳定的环境
- 大量照片需要下载的场景
- 对下载时间有严格要求的业务
- 需要高可靠性的照片同步服务
